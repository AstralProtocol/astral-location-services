## Direction findings (options for the maintainer, not ranked against bugs)

1. **Deliver offchain attestation resolution (`{uid, uri}`)** — documented as a
   first-class input (SPEC.md:217-220) but hard-throws "not yet implemented"
   (`input-resolver.ts:42-44`, `// TODO: Phase 2`); SDK types already accept it.
   Strongest stated-but-undelivered signal in the repo. Effort L (coarse):
   fetch/timeout/size limits, UID recomputation, EIP-712 verification, SSRF
   constraints on allowed URI schemes. Suggested as a design/spike plan first.
2. **Harden before expanding the verify plugin surface** — six plugins shipped
   against a spec that names two (docs/VERIFY-SPEC.md:528-547); the plugin
   interface makes new sources cheap, but ProofMode's unverified signatures
   (Plan 004) show the "verifiable" claim is ahead of the implementation.
   Define the verification bar a plugin must meet before being advertised in
   `GET /verify/v0/plugins`, and update VERIFY-SPEC.md to the six shipped
   plugins with their trust models. Effort M (coarse), mostly spec/decision work.

## Findings considered and rejected

(So nobody re-audits them.)

- **CORS default `'*'` when `ALLOWED_ORIGINS` unset** — acceptable: no credentialed CORS in use (auth is a header API key); staging/prod examples set explicit origins.
- **Requests without API key admitted at `public` tier** — by design (phased-auth decision recorded in SPEC/CLAUDE.md); rate-limited to the lowest tier.
- **Express 4 → 5 migration** — assessed, deferred: no EOL/security driver today; the real problem is the types mismatch (finding #10). Revisit when a driver appears.
- **In-memory rate limiter (`todos/020`)** — correct for the single-instance TEE deployment model; becomes a finding only if the service scales horizontally.
- **Default `astral:astral` Postgres credentials in Dockerfile/compose (`todos/010`)** — already tracked; severity mitigated by the DB being container-internal (localhost, by documented design). Keep the existing todo; not re-planned here.
- **Nonce → `Number()` conversion at `attestation.ts:256`** — precision loss is theoretical (nonces won't approach 2^53); not worth a change.
